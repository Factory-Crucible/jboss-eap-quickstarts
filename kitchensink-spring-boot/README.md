# Kitchensink Spring Boot Migration

Modernized Spring Boot 3 implementation of the classic JBoss *kitchensink* demo.  
It preserves 100 % functional parity (member registration and listing) while replacing
Jakarta EE components with Spring Boot conventions and Java 21 language features.

## 🗺️ Migration Overview

| Legacy JBoss EAP | Spring Boot Replacement |
| ---------------- | ----------------------- |
| CDI `@Inject` producers | Spring DI / configuration autowiring |
| Stateless EJB `MemberRegistration` | `@Service` + `@Transactional` `MemberService` |
| JAX-RS `MemberResourceRESTService` | Spring MVC `@RestController` |
| JPA Criteria queries | Spring Data JPA repository methods |
| Arquillian tests | Spring Boot Test + MockMvc / DataJpaTest |
| XML configs (`beans.xml`, `persistence.xml`) | `application.yml` auto-configuration |
| WAR deployment | Single executable **JAR** (`java -jar`) |

## 🚀 Setup & Running

Clone and enter the project:

```bash
git clone https://github.com/Factory-Crucible/jboss-eap-quickstarts.git
cd jboss-eap-quickstarts/kitchensink-spring-boot
```

### Development profile (default)

```bash
# compile, test, and run
mvn spring-boot:run
```

* Runs on `http://localhost:8080`
* Uses **in-memory H2** (`jdbc:h2:mem:kitchensinkdb`) auto-created & pre-loaded from
  `data.sql`
* H2 console available at `http://localhost:8080/h2-console` (JDBC URL above)

### Production profile

```bash
mvn spring-boot:run -Dspring-boot.run.profiles=prod
```

* Persists to a file-based H2 DB `./kitchensinkdb`
* Disables H2 console, sets Hibernate `ddl-auto=update`, lowers log verbosity

### Running the fat JAR

```bash
mvn clean package
java -jar target/kitchensink-spring-boot-1.0.0.jar
```

### Docker (optional quick start)

```bash
docker build -t kitchensink-sb .
docker run -p 8080:8080 kitchensink-sb
```

## 📑 API Reference

Base URL: `http://localhost:8080/api/members`

| Method | Path                | Description                          | Responses |
| ------ | ------------------- | ------------------------------------ | --------- |
| GET    | `/`                 | List all members ordered by name     | `200 OK` – `Member[]` |
| GET    | `/{id}`             | Fetch a member by ID                 | `200 OK` / `404 NOT FOUND` |
| POST   | `/`                 | Create a new member (JSON body)      | `201 CREATED` / `400 BAD REQUEST` (validation) / `409 CONFLICT` (email taken) |

Example **POST** request:

```bash
curl -X POST http://localhost:8080/api/members \
  -H "Content-Type: application/json" \
  -d '{"name":"Alice","email":"alice@example.com","phoneNumber":"1234567890"}'
```

## ✅ Testing

Run all unit and integration tests:

```bash
mvn test
```

Test suites:

* `MemberServiceTest` – isolated business logic via Mockito
* `MemberRepositoryTest` – JPA layer against embedded DB
* `MemberControllerIntegrationTest` – end-to-end REST with MockMvc (12 scenarios)

Coverage: domain validation, happy paths, error paths, duplicate email, etc.

## 🔧 Profiles

| Profile  | How to activate                     | Purpose & differences                               |
| -------- | ----------------------------------- | --------------------------------------------------- |
| default  | none (implicit) / `dev` alias       | In-memory DB, SQL init, verbose SQL logging, H2 UI  |
| prod     | `-Dspring-boot.run.profiles=prod`   | File DB, `ddl-auto=update`, H2 UI disabled, WARN logs |

## 📝 Migration Notes

1. **Entity**: `Member` now uses Lombok `@Data`, `@NoArgsConstructor`, etc.  
2. **Repository**: interface `MemberRepository extends JpaRepository` replaces manual `EntityManager` queries.  
3. **Service Layer**: business logic moved from EJB to Spring `@Service`; transactions via `@Transactional`.  
4. **REST**: Spring MVC controller handles validation and maps exceptions to HTTP codes.  
5. **Exceptions**: centralised `@ControllerAdvice` (`GlobalExceptionHandler`).  
6. **Configuration**: YAML profiles instead of XML descriptors.  
7. **Testing**: Arquillian removed; replaced with Spring Boot’s embedded testing stack.
